# Manuscript Editorial Quality Design

## 목적

Obsidian Manuscript Publisher의 저장, 삭제, 버전 관리, A4 출력, 고정 섹션, 유동 Step 기능은 유지한다. 이번 변경은 원고를 생성하는 표현 규칙과 이미지 품질만 개선한다. 목표는 원고 샘플 PDF처럼 Step 제목이 명사구로 끝나고, 생성 이미지는 장식적인 AI 그림이 아니라 실제 업무 화면 또는 출판용 전문 시각 자료처럼 보이게 하는 것이다.

## 변경하지 않는 영역

- 챕터 제목, `[이번 챕터에서는]`, `[한눈에 보기]`, `[미리 보기]`, `[실습하기]`, `[실전 활용하기]`, `[꿀팁 더하기]`의 순서
- `[한눈에 보기]`의 대상, 활용 도구, 준비물, 핵심 기능 4개 항목
- 주제에 따라 달라지는 Step 1부터 Step N까지의 유동 개수
- 대화별 Obsidian 분리 저장, 삭제, REST API 저장, 바이너리 검증, 불변 원고 버전
- A4 세로형 HTML·PDF 레이아웃과 이미지 바로 아래 캡션 배치
- Codex 내장 이미지 생성만 사용하며 외부 이미지 API를 사용하지 않는 원칙

## Step 제목 계약

Step 제목은 문장이 아니라 행동을 요약한 명사구로 작성한다. 제목 끝은 `준비`, `분석`, `설계`, `구성`, `구현`, `연결`, `설정`, `생성`, `비교`, `검증`, `수정`, `테스트`, `설치`, `배포`, `실행`, `적용`, `활용`, `정리`처럼 작업의 결과나 성격을 나타내는 명사가 된다.

허용 예시는 다음과 같다.

- `실제 양식과 업무 자료 준비`
- `품의 업무 분석과 스킬 설계`
- `K-에듀파인 CSV 생성 기능 구현`
- `생성 결과 검증과 오류 수정`
- `예약 실행 환경 설정`

`준비하기`, `설계합니다`, `만들어 보기`, `확인하세요`처럼 동사형·문장형으로 끝나는 제목은 허용하지 않는다. 제목을 명사형으로 만드는 것과 Step 순서를 고정하는 것은 별개다. 실제 작업 증거에 따라 필요한 Step만 선택한다.

## Step 본문 계약

각 Step은 원고 샘플처럼 한 문단 2~3문장으로 작성한다. 다음 세 역할이 자연스럽게 드러나야 한다.

1. 독자 또는 교사가 준비하거나 결정하는 일
2. Codex에 분석·제작·연결·테스트를 요청하는 일
3. 생성된 파일이나 결과에서 확인하고 수정하게 할 기준

본문은 현재형 존댓말을 사용한다. `Codex가 구현했습니다`, `사용자가 요청했습니다`, `시스템을 완성했습니다`와 같은 개발 결과 보고서형 과거 표현을 피한다. 대신 `Codex에게 CSV 생성 규칙을 코드로 작성하게 합니다`, `열 이름과 순서가 예시 파일과 일치하는지 확인합니다`처럼 독자가 따라 하는 실습형 문장으로 작성한다.

## 이미지 목적 분류

모든 이미지를 같은 인포그래픽으로 만들지 않는다. 원고 위치와 설명 목적에 따라 다음 `visual_kind` 중 하나를 선택한다.

| visual_kind | 용도 | 표현 기준 |
| --- | --- | --- |
| `ui_screen` | 설정, 실행, Codex 요청 화면 | 실제 데스크톱 앱처럼 정돈된 화면 계층과 현실적인 조작 상태 |
| `work_product` | 파일, 코드, 문서 제작 결과 | 편집기·파일 목록·문서 미리보기가 중심인 작업 화면 |
| `workflow_diagram` | 자동화 처리 흐름 | 출판용 도식, 제한된 색상, 명확한 방향과 단계 |
| `result_preview` | CSV, 문서, 웹앱, 메시지 결과 | 최종 산출물이 주인공인 결과 화면 |
| `field_scene` | 학교 업무·수업 적용 장면 | 과장되지 않은 현실적 업무 장면과 완성 결과의 사용 맥락 |

## 이미지 품질 계약

이미지는 AI가 생성하지만 전형적인 생성형 AI 장식물처럼 보이지 않아야 한다. 다음 요소는 금지한다.

- 로봇, 홀로그램, 빛나는 뇌, 떠다니는 아이콘, 네온 인터페이스
- 의미 없이 노트북을 바라보는 인물 중심 구도
- 실제 기능과 무관한 차트·버튼·메뉴
- 읽을 수 없는 한글, 가짜 문장, 뒤섞인 언어, 과도한 미세 텍스트
- 서로 다른 원근, 중복된 손가락, 왜곡된 기기와 같은 생성 결함
- 장마다 달라지는 색상·그림체·화면 비율

모든 프롬프트에는 이미지 목적, 핵심 산출물, 화면 상태, 16:9 가로 구도, 절제된 출판용 스타일, 금지 요소가 포함된다. UI 화면형은 짧고 검증 가능한 라벨만 사용하고 긴 본문을 이미지 안에 생성하지 않는다. 이미지 생성 후 Codex가 원본 크기로 다시 보고 목적 일치, 화면 구조, 텍스트 이상, 생성 결함, 전문적 완성도를 점검한다. 하나라도 실패하면 프롬프트를 수정해 다시 생성하며, 두 번째 결과도 실패하면 원고 출력을 중단한다.

최소 기술 기준은 너비 1200px 이상, 가로세로비 1.5 이상, PNG 또는 JPEG, 버전 폴더 내부 저장, SHA-256 일치다.

## 캡션 계약

모든 이미지를 `예시 이미지` 또는 `재현 화면`이라고 고정하지 않는다. 캡션은 이미지가 설명하는 내용에 따라 중립적으로 작성한다.

- `그림 1-04-1. Codex가 기사 선정 규칙을 정리하는 작업 화면`
- `그림 1-04-2. 국내외 기사 수집과 카카오톡 발송 처리 흐름`
- `그림 1-04-3. 두 기사가 하나의 메시지로 정리된 결과 예시`

실제 캡처가 아닌 이미지를 `실제 화면`이라고 단정하지 않는다. 캡션은 본문을 반복하지 않고 작업 상태, 결과, 확인 기준 중 하나를 설명하며 이미지 바로 아래에 유지한다.

## 데이터 계약

새 원고의 `manuscript.json`과 `asset-manifest.json`에는 다음 필드를 추가한다.

```json
{
  "visual_kind": "ui_screen",
  "quality_review": {
    "purpose_match": true,
    "professional_layout": true,
    "legible_content": true,
    "no_generation_artifacts": true,
    "no_generic_ai_motifs": true,
    "review_note": "작업 폴더와 생성 파일의 관계가 화면 중심에 명확하게 보임"
  }
}
```

기존에 게시한 원고 버전은 수정하거나 재검증하지 않는다. 새로 생성하는 버전부터 강화된 계약을 적용한다.

## 검증 및 실패 처리

검증기는 다음 오류 코드를 반환한다.

- `step_title_nominal_required`: Step 제목이 명사형 작업명으로 끝나지 않음
- `step_title_sentence_style_forbidden`: 제목이 `하기`, `합니다`, `하세요` 등 문장형으로 끝남
- `step_report_tense_forbidden`: Step 본문이 결과 보고형 과거 문장으로 작성됨
- `visual_kind_required`: 목적별 이미지 유형이 없음
- `visual_quality_review_required`: 시각 검토 기록이 없음
- `visual_minimum_resolution_required`: 이미지 너비가 1200px 미만임
- `figure_caption_format_required`: `그림 Part-챕터-순번.` 형식이 아님
- `unprofessional_prompt_contract`: 프롬프트에 목적·전문 스타일·금지 요소가 없음

검증 실패 시 HTML·PDF 렌더링과 Obsidian 게시를 시작하지 않는다.

## 성공 기준

- 고정 원고 양식과 유동 Step 수가 그대로 유지된다.
- 모든 Step 제목이 자연스러운 명사구로 끝난다.
- 각 Step 본문이 2~3문장의 실습형 현재형 존댓말로 출력된다.
- 이미지가 목적에 맞는 5가지 유형 중 하나로 분류된다.
- 로봇·홀로그램·깨진 글자·장식용 AI 이미지가 품질 검토에서 걸러진다.
- 캡션이 순번을 가진 출판용 문장으로 이미지 바로 아래에 출력된다.
- 기존 저장, 삭제, 버전 관리, 바이너리 업로드 테스트에 회귀가 없다.
